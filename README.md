# Dyscolab agent skills

[Agent Skills](https://agentskills.io) that teach coding agents how to model systems with
the Dyscolab libraries:

| Skill | What it covers |
| --- | --- |
| [`dyscolab-modeling`](skills/dyscolab-modeling/SKILL.md) | Declaring, simulating and analysing models with [poincare](https://github.com/dyscolab/poincare) (ODEs), [simbio](https://github.com/dyscolab/simbio) (reaction networks, compartments, SBML) and [jablonski](https://github.com/dyscolab/jablonski) (photophysics) |

The skill on `main` documents **poincare 1.3.0, simbio 1.3.0 and jablonski 0.5.0**.

## Install

The skill uses the open `SKILL.md` format, so it works with any agent that supports Agent
Skills.

### Bundled with the libraries (recommended)

poincare, simbio and jablonski ship the skill and install it into the environment at
`<environment>/share/agent-skills/dyscolab-modeling/`, matching the installed versions
(poincare 1.3.0 and newer).

**pixi projects:** link it into the agent's skills folder with
[pixi skills](https://pixi.prefix.dev/dev/integration/extensions/pixi_skills/). The
link follows the environment, so it updates with the libraries:

```sh
pixi global install pixi-skills                   # once
pixi skills manage --backend claude --scope local  # or another agent's backend
```

**Any environment:** copy it with the environment's Python, and run the same command
again after upgrading or adding a library:

```sh
python -m poincare.skill install --dest .agents/skills   # or .claude/skills, ~/.codex/skills, …
python -m poincare.skill check .agents/skills/dyscolab-modeling
```

### Separately, from this repository

This copy documents the releases listed in its SKILL.md, and doesn't follow the
installed versions.

**Any agent (Codex, Cursor, GitHub Copilot, Gemini CLI, Claude Code, Windsurf, Goose, …)**
with the [skills CLI](https://skills.sh):

```sh
npx skills add dyscolab/skills
```

**Claude Code**, as a plugin marketplace:

```sh
claude plugin marketplace add dyscolab/skills
claude plugin install dyscolab@dyscolab
```

**Manually:** copy `skills/dyscolab-modeling/` into your agent's skills directory (for
example `.agents/skills/`, `.claude/skills/` or `~/.codex/skills/`).

### The libraries

The skill expects the libraries in the Python environment the agent uses. poincare and
jablonski are on PyPI and conda-forge, simbio and rebop on PyPI. For example:

```sh
pixi add poincare jablonski && pixi add --pypi "simbio[io]" rebop
pip install poincare "simbio[io]" jablonski rebop
```

## Repository layout

```
skills/<name>/                   # GENERATED by scripts/build_skill.py, don't edit
templates/versions-section.md    # "Versions and environment" section of this copy
scripts/build_skill.py           # builds skills/ from the libraries pinned in pixi.toml
.claude-plugin/marketplace.json  # Claude Code marketplace manifest (points at skills/)
tests/                           # runs every example and validates the metadata
```

The skill content lives in the libraries, in `skill/share/agent-skills/dyscolab-modeling/`
of [poincare](https://github.com/dyscolab/poincare) (SKILL.md and the poincare parts),
[simbio](https://github.com/dyscolab/simbio) and
[jablonski](https://github.com/dyscolab/jablonski). Fix it there.

## Development

```sh
pixi run build             # regenerate skills/ from the pinned library releases
pixi run test              # Python 3.14
pixi run -e py312 test     # also py313
```

`main` only changes at releases. See [AGENTS.md](AGENTS.md).
